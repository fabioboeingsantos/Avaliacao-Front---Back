O que já está funcionando

O produto já tem autenticação, persistência, controle de estoque e o ciclo principal de pedidos. Build e lint do frontend passaram; a suíte backend e a publicação ainda precisam de validação.

Autenticação e permissões

O backend valida contas e aplica permissões por perfil nas operações protegidas.

  • Senhas com hash Argon2; sessão JWT em cookie HttpOnly por padrão por 24 horas.
  • Login, logout e restauração de sessão pela rota do usuário atual.
  • Perfis assinante e produtor, com isolamento das cestas por proprietário.

Pedido, separação e entrega

O fluxo de negócio principal está implementado na API e conectado às telas.

  • Criar e consultar pedidos; cancelar enquanto pendentes.
  • Separação em lote, desfazer lote e concluir após conferir os itens.
  • Confirmar recebimento ou marcar como entregue após sete dias.

Dados e regras da cesta

Persistência SQLAlchemy com migrações Alembic e configuração para SQLite ou MySQL.

  • Limite de produtos diferentes: 5, 8 ou 12 por tamanho.
  • O produtor define o estoque de cada produto; a API valida disponibilidade ao criar e separar pedidos.
  • Aviso de estoque baixo quando restam 10 unidades ou menos; o catálogo informa indisponibilidade quando zera.
  • 40 funções de teste backend estão no código; pytest não está instalado no ambiente virtual disponível.

Estoque e atualizações

O produtor controla a disponibilidade do catálogo e os dois perfis acompanham o andamento dos pedidos.

  • Somente o perfil produtor pode definir o estoque; pedidos respeitam as quantidades disponíveis.
  • Estoque baixo é sinalizado a partir de 10 unidades.
  • Sino de notificações apresenta mudanças de status para assinante e produtor enquanto usam o sistema.

Frontend e configuração

React e Vite apresentam os fluxos de assinante e produtor e chamam a API centralizada.

  • URL da API configurável por ambiente; produção usa o caminho relativo /api.
  • Caddyfile e proposta de infraestrutura estão no repositório, ainda sem deploy confirmado.
  • Com a API indisponível, há fallback demonstrativo em memória; pedidos locais não são persistidos.

Próximas etapas prioritárias

Validar antes de publicar

Executar a suíte backend e validar o fluxo integrado de estoque e pedidos; depois revisar o ambiente de produção.

1. Rodar verificações automatizadas

Instalar as dependências conforme os arquivos do projeto e registrar os resultados reais.

  • Backend: pytest -q dentro de backend.
  • Frontend: npm run lint e npm run build dentro de frontend.
  • Instalar as dependências de desenvolvimento e executar os 40 testes backend.
Prioridade imediata

2. Validar o fluxo integrado

Conferir frontend, API e banco usando sessões reais dos dois perfis.

  • Aplicar migrações e confirmar login, cadastro e restauração da sessão.
  • Testar estoque baixo, produto esgotado e tentativa de alteração pelo perfil assinante.
  • Assinante cria e cancela pedido; produtor separa, conclui e ambos recebem atualizações de status.
Próxima validação

3. Preparar publicação

Os arquivos atuais descrevem e esboçam a arquitetura, mas não comprovam que exista um ambiente publicado.

  • Provisionar domínio, HTTPS, servidor da API e banco MySQL protegido.
  • Configurar segredos e variáveis externas; ativar cookie Secure e restringir CORS.
  • Validar Caddy, proxy /api, migrações, backup, logs e smoke tests em ambiente real.
