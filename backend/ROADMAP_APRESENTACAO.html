Revisão do projeto

Como cada camada atende às necessidades.

Parte
O que faz e exemplo no sistema
Necessidade
React · App.jsx
Mantém a sessão e controla as telas. Ex.: `chamarApi('/cestas')` busca os dados e abre a `TelaSeparacao`.
Interface funcional
Rotas + Pydantic
Recebem e validam requisições. Ex.: `POST /cestas` confere o esquema `NovaCesta` antes do serviço.
API previsível
Serviços
Aplicam as regras. Ex.: `criar_cesta()` limita 5, 8 ou 12 itens; `separar_produto()` atualiza a situação.
Regras centralizadas
Repositórios + modelos
Persistem os dados. Ex.: `adicionar_cesta()` salva `Cesta` e `ItemCesta`; a busca respeita `usuario_id`.
Dados organizados
Banco + Alembic
Mantêm a estrutura do banco. Ex.: SQLite é local, MySQL é opcional e a migração `20261019_0003` vincula cestas antigas.
Persistência segura
Fluxo real: React chama a rota, a rota chama o serviço e o serviço usa o repositório. O acesso ao banco fica concentrado no repositório.

Plano de execução

O que precisa ser feito, na ordem.

1. Preparar o ambiente

Configurar o `.env`, preparar o banco, executar migrações e iniciar backend e frontend.

2. Validar o fluxo real

Testar login, criação da cesta, histórico, acesso do produtor e registro da separação.

3. Fechar segurança de produção

Ativar HTTPS, definir `JWT_COOKIE_SECURE=true`, restringir CORS e adicionar CSRF e CSP.

4. Consolidar a qualidade

Executar a suíte automatizada quando solicitado e depois criar testes frontend e E2E.

5. Atualizar a documentação

Revisar README, ambiente, migrações, roteiro de uso e critérios de entrega.

6. Publicar com controle

Configurar banco de produção, backup, logs, monitoramento e pipeline de build/deploy.
