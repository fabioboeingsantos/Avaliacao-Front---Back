  • Navegador: roda na máquina do usuário; é cliente; não precisa de porta de servidor pública.
  • Servidor web: roda em uma máquina de aplicação; atende em HTTPS na 443; recebe tráfego público e encaminha /api para a API interna na 8000.
  • API: roda em máquina interna do backend; atende na 8000; recebe tráfego do servidor web e não expõe acesso público direto.
  • MySQL: roda em máquina interna de dados; atende na 3306; recebe somente conexões da API; não recebe tráfego público.

2. Desenvolvimento e produção

Camada Desenvolvimento Produção
API FastAPI local, executada com fastapi dev main.py na porta 8000; pode apontar para SQLite local ou MySQL local. API em máquina interna, sem exposição direta ao público, ouvindo na 8000 e acessível somente pelo servidor web.
Tela React/Vite em ambiente local na porta 5173; a UI usa a API em host local e porta 8000. Tela servida em HTTPS na 443 e entregue ao navegador como origem pública; a mesma origem pode receber /api encaminhado para a API interna.

3. O caminho do login

  1. Máquina do usuário: o usuário clica em “Entrar” na tela do frontend.
  2. Servidor web: o navegador envia a requisição via HTTPS na 443.
  3. Servidor web → API: o servidor encaminha a chamada para a API interna em /api/autenticacao/login, na porta 8000.
  4. API: a API valida o usuário e a senha.
  5. API → MySQL: a API consulta o banco para confirmar a identidade e os dados da conta.
  6. API: se a autenticação for bem-sucedida, a API gera um JWT e define o cookie HttpOnly na resposta.
  7. Máquina do usuário: o navegador recebe a resposta e guarda o cookie do login.
  8. Máquina do usuário: nas próximas telas, o navegador manda esse cookie automaticamente junto com as requisições.
  9. Máquina do usuário + API: ao abrir ou recarregar a aplicação, o frontend chama /usuarios/me para restaurar a sessão; a validação final acontece na API e no banco.
O projeto atual já usa cookie HttpOnly e credenciais incluídas nas requisições do navegador, o que combina com a arquitetura proposta.

4. O que está chumbado

  • backend/configuracao.py: linha 35 — valor http://localhost:5173. Uso: servidor; padrão de origem permitida para CORS em desenvolvimento. Observação: é um valor de desenvolvimento e não representa a produção.
  • backend/.env.exemplo: linha 5 — valor BANCO_HOST=localhost. Uso: servidor; aponta o banco para a máquina local em desenvolvimento. Observação: em produção, o MySQL teria um host interno específico.
  • backend/.env.exemplo: linha 8 — valor FRONTEND_URL=http://localhost:5173. Uso: servidor; origem autorizada para CORS em desenvolvimento. Observação: não representa a produção.
  • frontend/src/App.jsx: linha 12 — valor ${window.location.protocol}//${window.location.hostname}:8000. Uso: navegador; monta a URL da API usando o host atual. Observação: isso funciona no desenvolvimento local, mas não deve ser tratado como endpoint de produção.
  • README.md: linha 73 — valor http://127.0.0.1:8000/docs. Uso: documentação do ambiente local de desenvolvimento. Observação: é referência de execução local, não de produção.
  • PASSO_A_PASSO_PROJETO.md: linha 325 — valor http://127.0.0.1:8000/docs. Uso: documentação local de desenvolvimento. Observação: aponta o ambiente do dev, não a arquitetura final.
  • PASSO_A_PASSO_PROJETO.md: linha 424 — valor http://localhost:5173. Uso: navegador; endereço do Vite em desenvolvimento. Observação: é uma origem local de dev; não deve ser usada como URL pública de produção.
