Grupos de usuários e permissões

O sistema possui duas personas. Cada conta pertence a um grupo e recebe somente as permissões necessárias para realizar seu trabalho.

1. Visão geral do acesso

O login identifica a conta. O backend consulta o grupo atual do usuário e verifica a permissão antes de executar uma rota protegida.

Produto 1:N Separaçõesprodutos.id → separacoes.produto_id. A combinação cesta + produto é única.

Observação do modelo: cestas.assinante mantém o nome textual usado no domínio e cestas.usuario_id faz o vínculo relacional com a conta. A aplicação usa o usuário autenticado para impedir que uma pessoa crie uma cesta em nome de outra conta.

4. Matriz de acesso às rotas

As permissões são verificadas antes da regra de negócio. Além do grupo, a API aplica o escopo correto: Aline vê apenas as próprias cestas; Vanderlei acompanha as cestas da produção. O cancelamento só é permitido à assinante enquanto o pedido estiver pendente. Rotas de cadastro, autenticação e saúde são públicas; o logout remove o cookie da sessão quando presente.

5. Fluxo de uma requisição protegida

A autorização fica concentrada na dependência exigir_permissao(), enquanto os serviços continuam responsáveis pelas regras específicas das cestas.

1. Requisição Frontend envia JWT ou cookie.
2. Identidade Backend valida o token e busca a conta.
3. Grupo Conta pertence a assinante ou produtor.
4. Permissão Matriz decide se a operação é permitida.
5. Serviço Regra da cesta é executada ou retorna erro.

Regra de segurança: um grupo desconhecido não recebe permissão por padrão. A API retorna 403 Forbidden quando a conta está autenticada, mas não possui autorização para a operação.
